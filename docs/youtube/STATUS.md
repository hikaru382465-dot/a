  - 描画は `--browser-executable=/opt/pw-browsers/chromium_headless_shell-1194/chrome-linux/headless_shell` を付ける（普通のchromeは失敗する）
  - 入口のファイルで `registerRoot()` を呼ぶ

- ひかるが環境の「ネットワークアクセス」設定に`soundeffect-lab.info`・`pixabay.com`・`maou.audio`を追加済み（2026-09-26）
  - `soundeffect-lab.info`：つながる。mp3への直リンクだけだと403で弾かれるので、`curl -A "Mozilla/5.0" -e "https://soundeffect-lab.info/sound/various/"`のようにUser-AgentとRefererを付ける必要がある
  - `maou.audio`：追加してすぐ、**同じセッションの中で**つながるようになった（新しいセッションを待たなくてもよかった）。ここもmp3ダウンロードにはReferer必須
  - `pixabay.com`：まだ403で弾かれる。maou.audioは追加後すぐ使えたので「設定は新しいセッションから」という前の予想は誤りだった可能性が高い → pixabay.comだけまだ何か設定ミス（打ち間違いなど）が残っていそう。ひかるにもう一度見てもらう
  - この設定は環境（クラウドの箱）ではなく別の場所にあるようで、箱を作り直しても消えない可能性がある
- ひかるが`openverse.org`・`wikimedia.org`・`commons.wikimedia.org`・`api.openverse.org`を追加（2026-09-26）。ネットワークの許可自体は通ったが、**実際に使おうとすると別の壁があった**
  - `api.openverse.org`：Cloudflareのボット対策（JS認証画面）で弾かれる。curlのような単純なアクセスでは突破できない
  - `commons.wikimedia.org`：「リクエストが多すぎる」で429エラー。おそらくこのクラウド環境が他のセッションと共有しているIPアドレスが、すでにWikimedia側のレート制限に達している
  - **結論：ドメイン許可だけでは自動取得できなかった。写真は今まで通りひかるがブラウザで探して送る方法を継続する**（ぱくたそ・Pixabayなど）
- Google Custom Search API（画像検索の自動化）も試したが**断念**（2026-09-27）
  - Google Cloud ConsoleでAPIキーを発行しようとしたところ「組織のセキュリティポリシーでAPIキーが許可されていません」というエラーが出た。ひかるが使っているGoogleアカウントが組織（Google Workspaceなど）に紐づいていて、管理者がAPIキー発行を禁止している可能性が高い
  - 別のGoogleアカウントでも同様にダメだったため、これ以上は追わないことに決定
  - **結論：写真探しの自動化はこれ以上進めない。今まで通りの分担（Claudeが検索して候補を提示→ひかるが保存して送る）を継続する**
