# ドット絵の技術（ひかるのリポジトリ games/farmhouse/pixel/）

**まず `games/farmhouse/pixel/README.md` の「描き方の決まり」を読む。** 次に、作るものに近い既存スクリプトを開いて、そのまま改造する（ゼロから書かない）。

## 基本のやり方（全部に共通）
1. **パレットだけで描く**：`pixel/palette.json`（系統の英字×明るさ0〜7）。新しい色が要るときは系統を足す（`ramp` に8色、暗い→明るい）。`pxl.load_palette()` で読み、`col(系統, 明るさ)` で色を取る。写真や縮小で出た中間色は、パレットの一番近い色に直す（最近傍）。
2. **numpy で1ドットずつ計算**：`Cv` クラス（`a` は H×W×4 のRGBA、`p(x,y,系統,明るさ)`、`mask(m,系統,明るさ配列)`）。形は式（楕円・ベジェ・ボロノイ・高さ場）、かげは「光の向き（左上）との内積」を3〜4段に区切る。
3. **輪郭は最後に1ドット**（暗い色。`np.pad` してから `np.roll`。**padなしだと端で回り込んで迷子の点が出る**）。
4. **網点（ベイヤー 4×4）で半透明を表す**：`BAY[y%4, x%4] < しきい値`。ぼかしやアルファは使わない。
5. **透過PNG**で保存（背景は alpha=0）。確認用に、別途チェック柄や海の上に載せた画像を出す。GIFは確認用（背景を敷く）。
6. **作ったら必ず拡大して自分の目で見る**（×6〜8）。次の点検をしてから渡す：迷子の1ドット／ふちの点線／見切れ（アニメは最大に広がるコマで枠を決める。余白6ドット）／足もとの高さがそろっているか／パレット外の色がないか。
7. **点数は厳しく付ける**（ひかるは自分の絵を20点と評価した実績あり。自己評価が甘いとずれる）。弱いところを3つ書き、「今すぐ／あとで」の道具のアドバイスを添える。

## 失敗から学んだこと（同じ失敗をしない）
- **ランダムなノイズで質感を出すと「ポツポツ」になる**。手描きタイル、または高さ場・面ごとのかげで出す。
- **ふちの1ドット線が回り込む**（`np.roll`のみ）→ 必ず `np.pad` してから。
- **アニメが見切れる**（波紋・しぶきは広がる）→ 最大のコマに合わせて枠を決め、余白をつける。
- **視点がそろわない**：島・イカダ・海は2:1（約30度）、水しぶきは45度。混ぜるときは大きさと角度の差を先に伝える。
- **縮小（半分）で絵が崩れる**→ 平均してパレットの最近傍に直すか、最初から小さい版を作る（`paint(…, 0.6)` のように倍率つきで）。
- **形が読めない絵は点数が低い**：袋や布は、前の版では何かわからなかった。形の輪郭と代表的な特徴（持ち手・結び目・縞・ぬい目）を先に決める。
- **カタログ切り出しで輪郭が欠ける／暗い側面が透明になる**（かまど・箱）→ `cutout()` ではなく `plane_cut(box, shrink, seal=2〜3)`。`seal` は暗い輪郭のすきまをふさいでから外側を塗りつぶす（面の中が背景あつかいになるのを防ぐ）。脚のあいだが透けるもの（干し魚だな）は `seal=0`、切り出し枠は脚の先より少し大きく。
- **似た絵の使い回しより、既存スクリプトに倍率や色の引数を足す**ほうが速い（`NET_SCALE`, `SPLASH_SCALE`）。

- **AI絵を切り出すとき、色数をへらさない・平均で縮めない**（ひかるの決まり）。`quantize` はしない、縮小は `Image.NEAREST`（元の点を拾う）。わざと色を変えるのは粘土・干物など、ひかるが決めた物だけ。

- **縮めて切ると輪郭がギザギザになる**（ひかる指摘）→ 新しいシートの置き物は縮めず（`cutlib.cut_checker(..., shrink=1)`）、ゲームでは `c.sprite(..., {smooth:true})`（ミップマップつきのなめらかな縮小）で出す。entry に `hi: 3` を付けると `objects.js` が大きさを3倍にそろえる。

- **切り出し範囲が絵よりせまいと、見切れる**（魚の図鑑で4種：フグ・イカ・カサゴ・ウナギ）→ `cutlib.LAST_TOUCH`（範囲のふちに絵がふれていたらTrue）で自動チェック。`make_fish.py` は、ふれていたら4pxずつ広げる。新しい切り出しでも、同じチェックを入れる。

- **足のすきま・ひげの輪にとり残された白い背景**（エビ・カニ）→ `cut_checker(..., pocket=900, fringe=6, pocket_min=12)`。外とつながっていない小さい白い面を消し、白っぽいふちも消す。半透明の絵（クラゲ）や、体の中の白いつや（ハイライト）は消えるので、必要な絵だけに使う（`make_fish.py` の `CLEAN_FOR`）。

- **AI絵に、絵の中を横切るうすい白い線（つなぎ目）があると、フードなどの上が消える**→ `cut_checker(..., seam=True)` で、線を上のとなりの色でうめてから切る。背景が真っ白な絵は `bgthr=(238, 14)` で、うすい色の服を背景とまちがえない。

- **作る担当と評価担当を分けると点が上がる**：評価は絵だけを見て、弱い所トップ3を「どこ（行・列）／何が問題／どう直すか」で出す。作る担当は点数を見ずに直す。「壊さないこと」も毎回伝える。前の版とドット単位で比べさせる。

- **見本を入れると白が減りやすい**：色を絞ったり面で分けたりするとき、「このキャラの目印の色（道着の白）」が減らないよう、色の割合も指示に書く。見本は「画づくり」だけまねて、キャラは別にする。

- **大きさは見本のドット数に合わせる**：見本を測る（1ドットの幅を色の変わり目から求め、キャラの外形をドット数にする）。32×48では見本の約1/5のドットしかなく、顔も細部も足りなかった。
- **言葉の指示は実行されないことがある**：同じ指摘が2回直らなければ、1ドットずつの格子（例：目11×6、靴12×4）で渡す。報告された直しは「何ドット変わったか」を数えさせる。

## 参考絵をネットで探す（ひかるは「調べてやって」と頼む）
- 作る前に `WebSearch`（standard）で「opengameart <もの> pixel art CC0」を調べ、出てきた OpenGameArt のページを `curl` で取る（この環境から opengameart.org は開ける。素材サイトによっては止められる）。ページ内の `https://opengameart.org/sites/default/files/….png` を、**空の新しいフォルダ**（例 /tmp/claude-0/webref/…）にダウンロードし、`python -I` で開き、`Read` で画像として見る。
- 見る点：ドット数（例：りんごは約21×22）、色数（りんごは赤3＋暖色1＋緑2＋ふち）、つやの形、かげの形。測った数字を作り方に入れる。ライセンスは CC0 のものだけ使い、**参考にするだけで、そのままコピーしない**。
- 学んだこと（りんご）：少ない色で大きな面／明るい側は暖色へ色ずらし／つやは細い弧／かげは三日月／ふちは暗い赤。リアルにしたいときも、帯（段）を増やすより、この整理が効く。
