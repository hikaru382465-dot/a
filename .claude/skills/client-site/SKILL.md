# お客さんの案件を進める

ひかるさんはプログラミング初心者の会社員（本業は施工管理）で、平日夜と土日に副業でホームページを作っている。スマホから指示することが多い。コードはこちらが書き、ひかるさんはお客さんとのやりとりと確認を担当する。

このスキルの目的は、**お客さんに渡しても恥ずかしくない品質を、毎回同じ手順で出すこと**。架空のサンプルと違い、間違った電話番号ひとつでお店が損をするので、確認の手順を省かない。

## 最初に決めること：どちらの仕事か

- **新しくサイトを作る** → 下の「制作の流れ」
- **今あるサイトの文章・画像を差し替える** → `references/update-jobs.md` を読んで、その流れに従う
- **見積書・請求書を作る** → `references/billing.md` を読んで、その流れに従う。お客さんの名前や金額は公開リポジトリに入れず、`private/` にだけ置く

## 引き受けてよい範囲

ココナラの出品文で約束した範囲を超えないようにする。超えると、低評価やトラブルにつながる。

- 対応する：1ページのサイト、スマホ対応、Googleマップ、写真ギャラリー、SNSや外部サービスへのリンク
- 自分で作らない：ネットショップ、予約システム、会員登録、問い合わせフォームの仕組み。お金や個人情報を扱い、納品後も管理が必要になるため
  - 代わりに、BASE・STORES・STORES予約・リザーブ・Googleフォームなどの**お客さん名義のアカウント**へリンクする、または埋め込む
- 約束しない：検索順位、独自ドメインの取得（相談されたら、お客さん自身で取ってもらう形を案内する）

範囲外の要望が来たら、断る理由と代わりの方法をひかるさんに説明し、お客さんへの返信文も用意する。

## 制作の流れ

### 1. 情報をそろえる

`references/intake.md` のヒアリング項目と照らし合わせて、足りない情報を洗い出す。

**事実は作らない。** 住所、電話番号、営業時間、料金、スタッフ名、お客様の声などは、お客さんからもらったものだけを使う。足りないものは本文に `【要確認：〇〇】` と書いて仮置きし、ひかるさん向けに「お客さんに聞くことリスト」と、そのまま送れる質問文を出す。架空のサンプルとは違い、それらしい値で埋めると、そのまま公開されてしまう危険がある。

お客様の声や実績の数字（「創業25年」「施工実績1,200件」など）は、お客さんが書いてほしいと言ったものだけを載せる。

### 2. 作る場所と名前を決める

- 置き場所：`works/<slug>/index.html`（`<slug>` はお店の名前を英数字にしたもの。例：`yamada-seikotsu`）
- お客さんの写真：`works/<slug>/images/` に入れ、わかりやすい英数字のファイル名にする
- 1つのHTMLファイルにCSSも書く。既存のサンプル（`works/cafe/` など）と同じ作り方にすると、ひかるさんが後から見比べやすい

### 3. 見た目の方向性を決める

色・書体・レイアウトを「なんとなく」選ばず、そのお店らしさに合わせて理由を持って決める。`references/design-direction.md` を読んで、その手順に従う。ここを丁寧にやると、量産している他の出品者のサイトと差がつく。

### 4. 作るときの決まりごと

- 色は `:root` にまとめて定義する（後で色を変えてほしいと言われたとき、1か所で直せる）
- スマホ幅（390px前後）を基準に作り、左右に16px以上の余白を取り、横スクロールを出さない
- 電話番号は `<a href="tel:...">` にして、スマホで押すと電話できるようにする
- 地図はGoogleマップの埋め込み（`iframe`）を使う。お客さんの住所で埋め込みURLを作る
- 画像には中身がわかる `alt` を付ける
- `<title>` は「お店の名前 | 地域 業種」の形、`<meta name="description">` にお店の紹介を1文で入れる
- 写真がないときはフリー素材（Unsplashなど商用利用できるもの）を使い、お客さんに「仮の写真です」と伝える文面を用意する
- ポートフォリオ用の「※これは制作サンプルです」の帯（`.sample-bar`）は、お客さんのサイトには付けない
- **確認用に公開している間は、`<head>` に `<meta name="robots" content="noindex">` を入れる**。お客さんがOKを出す前の下書きが検索に出てしまうのを防ぐため。納品するときに外す

### 5. 確認する

作ったら、必ずチェックスクリプトを動かす。

```bash
node .claude/skills/client-site/scripts/check_site.cjs works/<slug>
```

スクリプトがすること：
- スマホ幅とパソコン幅で横スクロールが出ていないか
- `【要確認】`、`○○`、`000-0000`、`サンプル` などの仮置きが残っていないか
- `alt` のない画像、存在しない画像ファイル、`tel:` リンクのない電話番号
- `noindex` が入っているか（確認中なら入っているのが正しい、納品時は外す）
- スマホとパソコンの画面の画像を `.check/<slug>/` に保存する

`FAIL` が出たら直してから進む。ただし、お客さんに途中経過を見てもらう段階では、`【要確認】` のFAILだけは残ってよい。その場合は、まだ埋まっていない箇所として確認のお願いメッセージの中で伝える。**納品するときはFAILを0件にする。** `WARN` は理由があれば残してよいが、ひかるさんに内容を伝える。

保存された画面の画像はSendUserFileでひかるさんに送り、スマホで見た目を確認してもらう。ひかるさんの目で見るのが最終確認になる。

### 6. お客さんに見てもらう

ひかるさんのGitHub Pagesで確認用に見てもらう。

- 確認用URL：`https://hikaru382465-dot.github.io/a/works/<slug>/`
- お客さんに送るメッセージは `references/messages.md` の「確認のお願い」を使う
- ポートフォリオ（トップの `index.html`）には、お客さんの許可なく載せない

### 7. 修正する

修正は2回まで無料。3回目以降は有料オプション（3,000円/回）になる。修正の依頼を受けたら、何回目かをひかるさんに伝える。無料の範囲を超えそうなときは、お客さんへの伝え方の文面も用意する。

### 8. 納品する

1. `noindex` を外す
2. チェックスクリプトをもう一度動かし、`FAIL` と仮置きがないことを確かめる
3. `works/<slug>/` をzipにまとめ、`.check/<slug>/` の下に置く
4. `references/messages.md` の「納品のご連絡」をもとに、納品メッセージを作る
5. 公開先について案内する：お客さんのサイトをひかるさんのアカウントに置き続けると、ひかるさんがやめたときにサイトが消えてしまう。お客さん名義で公開する方法（お客さんのサーバーにアップロード、またはお客さん名義のGitHub PagesやNetlifyなど）をひかるさんと相談して決める

### 9. 記録する

作業が終わるたびにコミットし、プッシュする。コミットメッセージは日本語で、何をしたかがわかるように書く（例：「山田整骨院：料金表を追加」）。

## ひかるさんへの伝え方

- 専門用語はできるだけ使わない。使うときは短く説明する
- 最後に「ひかるさんが次にやること」を番号付きで書く
- お客さんに送る文章は、コピペしやすいようにコードブロックに入れる
- お客さんに送る文章を書いたら、送る前に `references/customer-writing.md` の観点で読み返す。テンプレそのままに見えないか、言い回しが不自然に硬くないかを確認する
- ココナラやクラウドワークスでは、メールアドレス・LINE・電話番号などサイトの外で連絡を取る情報をメッセージに書かない（規約違反になる）。お客さんのお店の電話番号をサイトに載せるのは問題ない
