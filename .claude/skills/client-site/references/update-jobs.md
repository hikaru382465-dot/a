# 文章・画像の差し替え案件

ココナラの2つ目のサービス（`docs/coconala-listing-update.md`）の案件。基本料金は**5か所まで**。6か所目以降は有料オプション（5か所ごとに2,000円）。

## 1. 購入前の確認

お客さんからサイトのURLが届いたら、どうやって作られたサイトかを見分ける。

| 見分け方 | 作り方 | 対応 |
|---|---|---|
| ページのソースに `wp-content` がある | WordPress | ✅ 文章・画像の差し替えのみ |
| `wix.com`、`peraichi`、`jimdo` などの文字がある | 各サービス | ❌ 今は対応していない |
| 上のどれでもない | たぶんHTML | ✅ ファイルをもらえれば対応 |

この環境から外のサイトを開けないことがある。開けないときは、ひかるさんにスマホでページを開いてもらい、スクリーンショットか、ページのソース（URLの前に `view-source:` を付ける）を見せてもらう。

修正の数を数えて、5か所に収まるかをひかるさんに伝える。数え方がお客さんとずれるとトラブルになるので、「どこを、どう変えるか」を1か所ずつ番号付きで書き出し、お客さんに確認してもらう文面も作る。

## 2. HTMLのサイトの場合

1. お客さんからファイル一式をもらう（ココナラのメッセージに添付、またはzip）
2. `works/<slug>-update/` に置く
3. 変更前の状態でコミットしておく。何を変えたかを後で見せられるようにするため
4. 依頼された箇所だけを直す。頼まれていないところは、気づいても勝手に直さない（気になる点はひかるさんに伝え、お客さんに提案するかを任せる）
5. `node .claude/skills/client-site/scripts/check_site.cjs works/<slug>-update` で確認する。もとのサイトにあった問題が `WARN` や `FAIL` で出ることがある。今回の修正で増えたものでなければ、そのままにしてひかるさんに伝える
6. 変更前と変更後の違いを、お客さん向けの一覧にする（「1. 営業時間：10:00〜18:00 → 9:00〜19:00」のように）
7. 直したファイルをzipにして渡す。サーバーへのアップロードをお客さんから頼まれた場合は、やり方をひかるさんと相談する

## 3. WordPressのサイトの場合

こちらからはWordPressの管理画面を操作できない。ひかるさんが自分で管理画面を操作するので、手順を案内する役になる。

1. **お客さんのパスワードは預からない。** お客さんに作業用の「編集者」アカウントを作ってもらう。作り方を聞かれたら、次の文面を使う

```
お手数ですが、作業用のアカウントを作成していただけますでしょうか。

1. WordPressの管理画面にログイン
2. 左のメニューから「ユーザー」→「新規追加」
3. ユーザー名とメールアドレスを入力（メールアドレスは、ココナラのメッセージでお伝えする方法ではなく、お客様の方で任意のものをご用意ください）
4. 「権限グループ」を「編集者」にして「新規ユーザーを追加」

作業が終わりましたら、このアカウントは削除していただいて大丈夫です。
```

   ※ココナラの外で連絡を取る情報になるので、ひかるさんのメールアドレスはメッセージに書かない。ログイン情報の受け渡し方は、ココナラのルールを確認してから決める

2. ひかるさんがスクリーンショットを送ってくれたら、どこを押せばよいかを1ステップずつ案内する
3. 作業が終わったら、変更一覧を作り、お客さんに「作業用アカウントを削除してください」と伝える文面を用意する
