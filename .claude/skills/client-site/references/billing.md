# 見積書・請求書

`scripts/make_document.cjs` で、データ（JSON）からA4のPDFを作る。

## 大事な前提

### お客さんの情報を公開リポジトリに入れない
このリポジトリは公開されている。お客さんの名前・金額、ひかるさんの本名・住所・口座番号は、**`private/` フォルダにだけ置く**（`.gitignore` 済みで、コミットされない）。コミットする前に `git status` で `private/` が出ていないことを確かめる。

`private/` はこの作業環境の中にしかなく、セッションが終わると消える。作ったPDFはすぐにSendUserFileでひかるさんに送り、ひかるさんのスマホに保存してもらう。

### どのサイト経由の取引か
| 取引 | 支払い方法（payment） | 書類 |
|---|---|---|
| ココナラ・クラウドワークス・ランサーズ経由 | `"platform"` | お金は必ずサイト経由で払ってもらう。**振込先も連絡先も載せない**（スクリプトが自動で外す）。サイト外での支払いは規約違反になる |
| 知り合いなど、直接の取引 | `"bank"` | 振込先を載せる |

ココナラは、購入者に領収書をココナラ側で発行できる。サイト経由の取引では、請求書はお客さんに頼まれたとき（会社の経理で必要など）だけ作ればよい。見積書は、提案やココナラの見積もり機能と合わせて使う。

### 金額と税金
- 金額はすべて**税込**で書く（ココナラの価格も税込のため）
- ひかるさんは適格請求書発行事業者（インボイス）の登録をしていない前提なので、**登録番号は書かない**
- お客さんから「インボイス対応の請求書がほしい」と言われたら、自分で判断せず、ひかるさんに伝えて税務署や税理士に相談するよう勧める

## 差出人の登録（最初の1回）

`private/profile.json` がないと作れない。ないときは、ひかるさんに聞いて作る。見本は `assets/profile.example.json`。

- `name`：書類に載せる名前。サイト経由の取引だけならニックネーム（ひかる）でもよい。直接の取引で振込をお願いする場合は、口座名義と合う本名にする
- `address`、`contact`：省略してよい
- `bank`：直接の取引で振込をお願いするときだけ必要

## 書類の作り方

1. `assets/example-estimate.json`（見積書）または `assets/example-invoice.json`（請求書）を `private/billing/` にコピーする
2. ファイル名は `<番号>-<お客さんのslug>.json`（例：`E-2026-002-yamada-seikotsu.json`）
3. 中身を書き換える

| 項目 | 内容 |
|---|---|
| `type` | `"estimate"`（見積書）か `"invoice"`（請求書） |
| `number` | 見積書は `E-年-連番`、請求書は `I-年-連番`。`private/billing/` の既存ファイルを見て、続きの番号にする |
| `date` | 発行日（`YYYY-MM-DD`） |
| `client`、`honorific` | お客さんの名前と敬称。会社・お店なら `御中`、個人なら `様` |
| `subject` | 件名 |
| `validUntil`、`delivery` | 見積書だけ。有効期限（ふつうは発行日から1か月）と納期 |
| `dueDate` | 請求書だけ。支払期限 |
| `payment`、`platform` | 上の表のとおり。`platform` にはサイト名（ココナラ など） |
| `items` | 内容、数量、単位、単価（税込）。`note` で小さな補足を付けられる |
| `notes` | 備考。修正回数の決まりや、含まれないこと |

4. PDFを作る

```bash
node .claude/skills/client-site/scripts/make_document.cjs private/billing/<ファイル名>.json --png
```

`--png` を付けると、同じ内容の画像もできる。画像を見て、名前・金額・日付に間違いがないか確かめてから、PDFと画像をSendUserFileでひかるさんに送る。
